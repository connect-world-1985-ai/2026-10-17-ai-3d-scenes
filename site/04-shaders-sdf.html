Part II — Fundamentals

Shaders, noise and signed distance fields

Shaders are small programs that run on the GPU, thousands at once. Water, windows, sky, terrain detail, the glow on a neon sign: in most impressive web demos, the most visible effects are shader code, not models. This is also where LLMs shine and fail most visibly. They know the classic snippets by heart, but a single sign error gives a black screen.

Vertex and fragment shaders

The two programs are written in GLSL (WebGL) or WGSL (WebGPU). Three.js also has its own node language, TSL, which compiles to both. Data flows in as attributes (per vertex), uniforms (same for the whole draw: time, sun direction) and textures; it flows from vertex to fragment shader as varyings, interpolated across each triangle.

// fragment shader: a window grid on a building face, no textures
uniform float uNight;
varying vec3 vWorld;
void main() {
  vec2 cell = vec2(vWorld.x / 2.2, vWorld.y / 3.2);       // 2.2 m wide cells, 3.2 m storeys
  vec2 f = fract(cell);                                    // position inside the cell, 0..1
  float win = step(0.2, f.x) * step(f.x, 0.8) * step(0.3, f.y) * step(f.y, 0.85);
  float lit = step(0.55, fract(sin(dot(floor(cell), vec2(41.3, 289.1))) * 43758.5453));
  vec3 wall = vec3(0.45, 0.42, 0.40);
  gl_FragColor = vec4(mix(wall, vec3(1.0, 0.75, 0.4) * lit * uNight, win), 1.0);
}

That is essentially the window shader of this guide's city demo. Three ideas do all the work: fract() for repetition, step() for hard edges, and a hash of the cell index for per-window randomness.

In Three.js you write custom shaders three ways:

  • ShaderMaterial: full control, but you write all the lighting yourself.
  • onBeforeCompile: inject code into a built-in material and keep PBR.
  • TSL node materials, required for WebGPURenderer. WebGPURenderer supports neither ShaderMaterial nor onBeforeCompile. Verified This is a major reason agents still default to WebGL.

Noise: the source of all natural detail

Pure randomness looks like TV static. Natural surfaces (clouds, terrain, water, stone) have structure at many scales. Shader noise functions provide smooth pseudo-randomness:

  • Value noise and Perlin (gradient) noise. Perlin 1985, then "Improving noise" 2002, which introduced the quintic fade 6t⁵−15t⁴+10t³. Verified
  • Simplex noise: cheaper in higher dimensions, fewer directional artefacts.
  • Worley (cellular) noise (Worley 1996): cell-like patterns for stone, foam, caustics.
  • fBm (fractional Brownian motion): add several octaves of noise, each with double the frequency and half the amplitude. Five to eight octaves of fBm is the standard terrain or cloud recipe; domain warping (feeding noise into noise) gives marbled, eroded looks.

The best introduction is The Book of Shaders (chapters on noise and fBm). The reference snippets most agents reproduce are by Inigo Quilez (iquilezles.org). He publishes his snippet code under MIT, but his ShaderToy artworks remain protected. Verified

Signed distance fields and raymarching

A signed distance function (SDF) returns, for any point in space, the distance to the nearest surface: negative inside, positive outside. A sphere is length(p) - r. Shapes combine with min (union), max (intersection) and smooth-min (blend). Space can be folded: p.xz = mod(p.xz, 10.0) - 5.0 repeats an object infinitely in two directions for the cost of one.

Sphere tracing (Hart 1996) renders it: from the camera, step along each pixel's ray by the SDF value. That step is guaranteed not to pass through anything. Stop when the distance is tiny (a hit) or after N steps (a miss). Verified

Everything else follows from the same function:

  • Normals come from the SDF's gradient (sample it at six nearby points).
  • Soft shadows come from marching towards the sun and remembering the closest near-miss.
  • Ambient occlusion comes from sampling the distance a few times along the normal.

No meshes, no textures: one full-screen triangle and one fragment shader.

Try it: one fragment shader draws a city

This demo is raw WebGL with no library, so it works offline. Each building is one box SDF, repeated across space with mod; height varies with a hash of the cell index. A blob in the middle is smooth-min blended into the ground. Things to try:

  • Drop max steps to 16 and watch distant buildings vanish: the ray gives up before reaching them.
  • Switch the view to step heat map to see where the GPU works hardest.
  • Set the smooth-min k to 0 to see a hard union.

Where this shows up in "AI-made" demos

  • ShaderToy-style scenes. Endless terrains, seas and abstract cities in one shader. Famous examples: Seascape (TDM), a noise heightfield with 32 march steps, neither Gerstner nor FFT; iq's Elevated and Rainforest. Verified When an LLM writes "a realistic ocean shader", it often reproduces a version of Seascape. Inference
  • Inside mesh scenes. Sky domes, clouds, fog volumes and water surfaces are often raymarched or noise-driven inside an otherwise normal Three.js scene.
  • Licence caution. ShaderToy's default licence is CC BY-NC-SA 3.0 unless the author states otherwise. A model "recalling" a famous shader can bring a non-commercial licence along with it. Verified (licence) / Inference (risk)

Typical shader failures (and how agents fix them)

SymptomUsual causeFix
Black or magenta screen, console says "shader compile error"GLSL type errors (1 instead of 1.0), wrong GLSL version, missing precisionRead the compile log; agents fix this quickly when they see the error text
Holes or "onion rings" in raymarched surfacesToo few steps, or a distance function that is not a true distance (after scaling or twisting)More steps; multiply the step by 0.5–0.8 for non-exact SDFs
Banding in sky gradients8-bit output of smooth gradientsAdd tiny noise (dithering) before output
Noise looks the same everywhere or "swims"Hash precision issues on mobile GPUs, or time added to the wrong coordinateBetter hash functions; animate the noise domain, not the output
Works on desktop, black on phoneMobile precision (mediump) or loop limitsUse highp where supported; constant loop bounds
